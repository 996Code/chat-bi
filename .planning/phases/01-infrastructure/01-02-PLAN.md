threat_model:
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → /auth/login | Untrusted email+password input, rate-limited via in-memory lock |
| Client → /auth/register | Untrusted email+password, validated against schema |
| Server → Email (SMTP) | User-provided SMTP config — may fail; graceful degradation required |
| JWT → Client | Tokens in httpOnly cookies (not localStorage) to prevent XSS theft |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Information Disclosure | password_hash | mitigate | bcrypt cost 12, never return hash in any response; password field excluded from all Pydantic schemas |
| T-01-05 | Tampering | JWT tokens | mitigate | HMAC-SHA256 signed with APP_SECRET_KEY; verify on every protected route |
| T-01-06 | Denial of Service | login endpoint | mitigate | In-memory lock: 5 failures → 15min lock per email; dict with TTL cleanup |
| T-01-07 | Elevation of Privilege | refresh token rotation | mitigate | Old refresh token invalidated after rotation; store token jti in DB for revocation |
| T-01-08 | Information Disclosure | CORS | mitigate | Strict origin whitelist via CORSMiddleware; no wildcard; dev=localhost:5173, prod=configurable |
| T-01-09 | Spoofing | email verification | mitigate | itsdangerous signed token with 24h expiry; token verified before allowing datasource operations |
| T-01-10 | Spoofing | password reset | mitigate | itsdangerous signed token with 30min expiry; single-use; all refresh tokens revoked on reset |
</threat_model>

    2. Create `backend/app/schemas/auth.py`:
       ```python
       from pydantic import BaseModel, EmailStr, field_validator
       import re

       class RegisterRequest(BaseModel):
           email: EmailStr
           password: str
           @field_validator("password")
           @classmethod
           def validate_password(cls, v):
               if len(v) < 8: raise ValueError("密码至少8位")
               if not re.search(r"[a-zA-Z]", v): raise ValueError("密码必须包含字母")
               if not re.search(r"[0-9]", v): raise ValueError("密码必须包含数字")
               return v

       class LoginRequest(BaseModel):
           email: EmailStr
           password: str

       class TokenResponse(BaseModel):
           access_token: str
           refresh_token: str
           token_type: str = "bearer"

       class RefreshRequest(BaseModel):
           refresh_token: str

       class PasswordResetRequest(BaseModel):
           email: EmailStr

       class PasswordResetConfirm(BaseModel):
           token: str
           new_password: str  # same validation as RegisterRequest

       class EmailVerifyRequest(BaseModel):
           token: str
       ```

    3. Create `backend/app/core/security.py`:
       - `hash_password(password: str) -> str`: uses `passlib.context.CryptContext(schemes=["bcrypt"], bcrypt__rounds=settings.bcrypt_rounds)`
       - `verify_password(password: str, hashed: str) -> bool`: uses `pwd_context.verify()`
       - `create_access_token(data: dict, expires_delta: timedelta | None = None) -> str`: uses `python-jose.jwt.encode()` with payload `{**data, "type": "access", "exp": expire_time}`
       - `create_refresh_token(data: dict) -> str`: same but `"type": "refresh"`, expires 7 days; includes `"jti": str(uuid4())`
       - `verify_access_token(token: str) -> dict`: decode, check `"type" == "access"`, return payload
       - `verify_refresh_token(token: str) -> dict`: decode, check `"type" == "refresh"`, return payload
       - `generate_password_reset_token(email: str) -> str`: uses `itsdangerous.URLSafeTimedSerializer(settings.secret_key)` with max_age=1800 (30min)
       - `verify_password_reset_token(token: str) -> str | None`: loads token, returns email or None if expired
       - `generate_email_verification_token(email: str) -> str`: itsdangerous with max_age=86400 (24h)
       - `verify_email_verification_token(token: str) -> str | None`: loads token, returns email or None

    4. Create `backend/app/api/auth.py` with 6 endpoints:
       - `POST /api/v1/auth/register`:
         a. Validate email not already in use
         b. Hash password with bcrypt (cost 12)
         c. Auto-create Tenant if first user: `Tenant(name="个人", slug=uuid4()[:8])`
         d. Create User with tenant_id, email_verified=False
         e. Generate email verification token (store token + expiry on user)
         f. Attempt to send verification email (if SMTP configured); if not, log token for dev
         g. Return `{"message": "注册成功，请查收验证邮件"}` (201)
       - `POST /api/v1/auth/login`:
         a. Check login lock (call `login_lock_service.check_lock(email)`)
         b. Look up user by email; if not found, return 401 `{"code": "INVALID_CREDENTIALS", "message": "邮箱或密码错误"}`
         c. Verify password; if wrong, call `login_lock_service.record_failure(email)`, increment `failed_login_attempts`, return 401
         d. If locked (5 failures), return 429 `{"code": "ACCOUNT_LOCKED", "message": "账号已锁定，请15分钟后重试"}`
         e. If not email_verified, still allow login but return `{"warning": "email_not_verified"}` in response
         f. Reset failed_login_attempts on success, call `login_lock_service.reset(email)`
         g. Create access token (15min) + refresh token (7d with jti)
         h. Return TokenResponse with `{"user_id": str(user.id), "email": user.email, "tenant_id": str(user.tenant_id)}`
       - `POST /api/v1/auth/refresh`:
         a. Verify refresh token, extract jti
         b. Verify token hasn't been revoked (check jti not in revoked set — in-memory dict for v1)
         c. Generate NEW access token + NEW refresh token (rotation — old jti added to revoked set)
         d. Return new TokenResponse
       - `POST /api/v1/auth/reset-password`:
         a. Find user by email; if not found, still return 200 (prevent email enumeration)
         b. Generate reset token via itsdangerous (30min)
         c. Send email with reset link (or log token if SMTP not configured)
         d. Return `{"message": "如果邮箱存在，重置链接已发送"}`
       - `POST /api/v1/auth/reset-password/confirm`:
         a. Verify token, extract email
         b. Hash new password
         c. Update user's password_hash, reset failed_login_attempts, clear lock
         d. Revoke ALL refresh tokens for this user (clear their jti entries)
         e. Return `{"message": "密码已重置"}`
       - `POST /api/v1/auth/verify-email`:
         a. Verify email token, extract email
         b. Set user.email_verified = True, clear token
         c. Return `{"message": "邮箱已验证"}`

    5. Create `backend/app/api/__init__.py`:

    1. Create `backend/app/services/login_lock_service.py`:
       - In-memory dict: `_login_attempts: dict[str, {"count": int, "locked_until": float | None}]`
       - `MAX_ATTEMPTS = 5`, `LOCK_DURATION = 900` (15 minutes in seconds)
       - `check_lock(email: str) -> bool`: returns True if locked (current time < locked_until). If lock expired, clean up and return False.
       - `record_failure(email: str) -> None`: increment count; if count >= MAX_ATTEMPTS, set locked_until = time.time() + LOCK_DURATION
       - `reset(email: str) -> None`: delete entry from dict
       - Background cleanup: on each call, prune entries where locked_until has expired + 300s buffer
       - NOTE: This is in-memory for v1 (user decision — Redis in production). Dict key is lowercase email.

    2. Create `backend/app/services/email_service.py`:
