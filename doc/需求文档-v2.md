# ChatBI v2 需求文档

> 基于：Claude Code 源码深度解读 + WrenAI/Vanna/DB-GPT/海泰竞品分析 + v1 48 条经验教训
> 核心转变：从"一次问答出 SQL"到"Claude Code 式多轮交互 + Agent 反思"
> 设计原则：安全默认（Fail-Closed）、分层可缓存、状态补偿、文件化记忆、热更新

---

## 一、产品定位

**一句话**：让不会 SQL 的人也能自助完成数据查询和可视化——像和 Claude Code 协作一样和 BI 系统协作。

**核心体验**：
- 不是"输入问题 → 等结果"，而是"输入问题 → Agent 思考 → 展示思考过程 → 用户可干预 → 出结果"
- 简单问题全自动，复杂问题 Agent 不确定时暂停问用户
- Agent 执行失败或结果异常时自己反思、修正
- 对话越来越长时自动压缩，不丢关键上下文

**对内工具**，支持 MySQL + PostgreSQL。

## 二、核心架构需求

### ARC-01: Agent 执行引擎 — while(true) 循环

**对标**：Claude Code `query.ts` 主循环

Agent 执行不是一次 LLM 调用，而是 while(true) 循环：
1. 组装上下文（用户问题 + 语义层 + Skills + 对话历史 + 结构化状态）
2. 调用 LLM，获取决策（生成 SQL？问用户？选表？）
3. 执行决策（生成 SQL → 校验 → 执行 → 自检）
4. 结果异常或失败 → 反思 → 修正 → 重新执行
5. 成功 → 生成图表 → 返回结果
6. 压缩检查 → 对话过长时自动压缩

**验收标准**：
- [ ] Agent 能在一次查询中多次调用 LLM（生成→执行→反思→修正→再生成）
- [ ] 每次 LLM 调用的完整 prompt + response 可导出查看
- [ ] Agent 调用链（Intent → Schema → SQL → Chart → SelfCheck）每步耗时 + token 用量可展示

### ARC-02: Agent 反思 — 4 个维度

**对标**：Claude Code compact 自检 + tool 错误回流

| 维度 | 触发条件 | Agent 行为 |
|------|---------|-----------|
| **生成前预思考** | 每次 SQL 生成前 | 先想清楚：需要哪些表？什么聚合？更好的写法？展示给用户 |
| **执行失败自愈** | SQL 执行报错 | 错误码映射 → 专项纠正 prompt → 重新生成 → 重新校验 → 重新执行（最多 2 轮） |
| **结果合理性自检** | SQL 执行成功 | 审视结果：返回 0 行？数字异常大/小？→ 怀疑 → 重新审视 schema → 修正 SQL |
| **追问主动优化** | 用户追问时 | 反思上一轮 SQL 是否最优 → 主动建议改进 |

**熔断器**：自愈连续失败 3 次 → 停止 + 返回明确错误 + 原始错误信息

**验收标准**：
- [ ] Agent 每次生成 SQL 前输出预思考内容（选表理由、聚合方式、注意事项）
- [ ] SQL 执行报错 → Agent 自动分析错误 → 修复 → 重试（用户看到"正在修复..."）
- [ ] SQL 返回 0 行 → Agent 输出"结果为空，可能原因：xxx，建议：xxx"
- [ ] 追问"上个月呢" → Agent 说"我注意到上一轮没用索引，这次建议加 xxx"

### ARC-03: 关键节点暂停 — Agent 主动请求用户确认

**对标**：Claude Code `AskUserQuestionTool` — "向用户提问"就是普通 Tool

Agent 在以下场景**主动暂停**请求用户确认：
- Schema 选择不确定（多张表都匹配，不知道选哪张）
- 结果自检异常（0 行 / 数字异常大 / 数据看起来不一致）

**实现方式**：Agent 调用 `ask_user` 工具 → 前端弹出确认表单 → 用户输入 → 作为 tool_result 返回给 Agent → 继续执行

**验收标准**：
- [ ] Agent 不确定选哪张表 → 暂停 → 展示候选表 + 说明 → 用户选择 → Agent 继续
- [ ] Agent 发现结果异常 → 暂停 → 说明怀疑原因 → 用户选择"继续"/"重试"/"修正"
- [ ] 暂停时显示 Agent 当前的思考状态和判断依据

### ARC-04: 多轮对话 + 上下文压缩

**对标**：Claude Code PostgreSQL Checkpointer + Store + compact + 状态补偿

**结构化状态存储（State Store）**：
- 每轮结束后，Agent 将结构化信息写入 State Store
- 包含：当前选中的表、当前 SQL、筛选条件、结果摘要、图表类型
- 追问时读 Store → 不需要从聊天历史里解析上下文

**对话历史管理**：
- 每轮对话结束自动生成一句话摘要
- 保留最近 2-3 轮完整历史 + 全部旧轮次摘要
- 上下文 token 超过 6K 或对话超过 6 轮 → 自动压缩旧轮次
- 压缩后补回：语义层 context + 当前 SQL + 筛选条件（状态补偿）

**会话持久化**：
- PostgreSQL Checkpointer 写入简单（append-only 思路）、恢复时重建状态
- 支持跨会话恢复（用户关闭页面再打开，继续之前的对话）

**验收标准**：
- [ ] 用户问"本月销售额"→ 追问"按品类拆分"→ Agent 知道当前在查 orders 表
- [ ] 用户问"上个月呢"→ Agent 复用上一轮的 schema context，不重新检索
- [ ] 对话超过 6 轮后自动压缩 → Agent 仍然能正确回答新问题
- [ ] 关闭页面重新打开 → 恢复之前的对话和上下文
- [ ] 压缩后用户仍能看到被压缩轮次的摘要（可展开）

## 三、AI 能力核心需求

### AI-01: 知识图谱 — AI 自动推断实体关系

AI 通过以下方式理解业务：
- **数据模型**：自动扫描表结构、字段、外键关系
- **配置**：人工补充的业务规则、领域术语、别名映射
- **知识图谱**：AI 自动推断实体关系 + 从历史查询中挖掘隐式关系 + 从用户反馈中学习

AI 自动推断流程：
1. 扫描数据库结构 → 根据表名、字段名、外键关系 → 自动推断实体关系
2. 分析 SQL 查询历史 → 发现隐式关系（两个表经常一起查 → 可能有业务关联）
3. 学习用户反馈 → 纠正过的 SQL 回流到知识库

人工只需校验和修正，不需要手动配置一切。

**验收标准**：
- [ ] 新数据源接入后，AI 自动生成初始知识图谱（实体 + 关系 + 字段语义）
- [ ] 同一对表被多次 JOIN 查询 → AI 自动补充关联关系
- [ ] 用户纠正过错误的表选择 → 下次相似问题不再选错
- [ ] 人工可以查看、编辑、删除 AI 推断的关系

### AI-02: 语义层 — JSON MDL + 自动扫描 + 人工修正

**对标**：WrenAI MDL 语义层 + 海泰 ContextKey 枚举 + Skills 外置

语义层定义（JSON 格式）：
- **Model**：表的中文显示名、描述、列定义、关系、指标、计算字段
- **Relationship**：1:1 / 1:N / N:1 关系，类型（INNER/LEFT），ON 条件
- **Metric**：预定义指标（名称、公式、描述），支持复合指标
- **Calculated Field**：计算字段（SQL 表达式）

数据源接入时：
- 自动扫描 → 生成初始语义层 JSON
- AI 自动推断列的中文语义、实体关系
- 人工校验和修正 → 不需要从零配置

**验收标准**：
- [ ] 新数据源接入后自动生成语义层 JSON
- [ ] 定义 "GMV = SUM(payment_amount)" 后，用户问"GMV"直接用预定义公式
- [ ] 定义 orders.user_id → users.id (N:1) 关系后，问"每个用户的订单数"自动 JOIN
- [ ] 语义层修改后即日生效（不需重启服务）

### AI-03: RAG 向量检索 — 两层检索

**对标**：WrenAI 三层 RAG + 海泰 Milvus + Claude Code Relevant Recall（最多召回 5 条）

**技术方案**：pgvector + BGE-large-zh Embedding（1024 维）

**两层检索流程**：
- **第一层**：向量相似度检索 → pgvector top-K 召回（K=20）
- **第二层**：LLM 精筛 → 从候选中选出最相关的 Models + Columns

**检索失败处理**：检索无结果 → 返回友好提示"无法匹配到相关表，请换一种问法"——**绝不 fallback 到随机选表**

**验收标准**：
- [ ] 用户问"销售额"→ 向量检索召回含 amount/price/revenue 的列
- [ ] Schema Linking 准确率 ≥ 85%
- [ ] 检索无结果时返回友好提示，不随机选表

### AI-04: SQL 生成 — 白名单 + 类型约束 + Skills

**对标**：Claude Code Prompt 分层 + 静态主干(可缓存) + 动态段(不可缓存)

**约束体系**：
- **白名单列名**：SQL 中出现的列名必须在语义层定义内
- **data_type 约束**：DATE 类型的列不能 SUM，DECIMAL 类型不能 DATE_FORMAT
- **Skills 注入**：SKILL.md 中的业务规则注入 system prompt
- **方言适配**：从 DataSource 配置动态获取 SQL 方言，不硬编码 "mysql"
- **拒绝生成**：Schema 检索无结果时，不强制 LLM 生成 SQL

**Prompt 分层缓存**：
- 静态段（可缓存）：语义层 context + Skills + 系统身份
- 动态段（不可缓存）：用户问题 + 对话历史 + 当前状态

**验收标准**：
- [ ] 生成的 SQL 只使用语义层定义的表和列
- [ ] 枚举列（status）的值必须在合法范围内
- [ ] 修改 SKILL.md 后下次查询立即使用新规则（热更新）
- [ ] MySQL 数据源用 LIMIT，PostgreSQL 数据源用 LIMIT（不硬编码方言）

### AI-05: 意图识别 — 5 种意图 + Pydantic 强约束

**对标**：Claude Code 5 种意图（TEXT_TO_SQL / CLARIFICATION / GENERAL / CHART_MODIFY / EXPLANATION）

**Pydantic 强约束输出**：
- LLM 必须输出结构化 JSON，不符合 schema 时重试
- 字段：intent(enum), normalized_question(str), confidence(float 0-1), reason(str)
- confidence < 0.6 → 自动降级为 CLARIFICATION（追问用户）

**5 种意图分流**：
- `TEXT_TO_SQL`："本月销售额"→ 走 SQL 生成链路
- `CLARIFICATION`："那个呢"→ 需要上下文补全或多轮关联
- `GENERAL`："你好"→ 通用对话，不查数据库
- `CHART_MODIFY`："换成饼图"→ 只改图表不改 SQL
- `EXPLANATION`："这个 SQL 什么意思"→ 解释已有结果

**验收标准**：
- [ ] 每种意图正确识别并分发到对应处理链路
- [ ] confidence < 0.6 的模糊问题自动追问
- [ ] normalized_question 提取核心查询意图（"帮我看看上个月的订情况"→"上月订单统计"）

### AI-06: 图表生成 — LLM 声明式 ECharts option

**对标**：WrenAI 声明式图表（LLM 生成 Vega-Lite JSON spec）+ Claude Code 专项 prompt

不是规则推断（v1 的 `"20" in value` 误判），而是 LLM 生成完整 ECharts option JSON。

**降级策略**：LLM 生成失败 → 降级为规则推断 + WARNING 日志

**Skills 图表约束**：
- 默认颜色主题、交互规则（是否可缩放、是否显示数据标签）
- 用户可指定覆盖（"画个饼图"→ 覆盖默认柱状图）

**验收标准**：
- [ ] 时间序列数据 → 生成折线图（xAxis.type = "time"）
- [ ] 分类聚合数据 → 生成柱状图（xAxis.type = "category"）
- [ ] option JSON 缺失必需字段 → 自动补全
- [ ] "把这个柱状图换成折线图"→ type 从 bar 改为 line，数据不变

## 四、安全与治理

### SEC-01: 安全默认原则（Fail-Closed）

**对标**：Claude Code `buildTool()` 默认值：并发不安全、非只读、需确认

所有操作默认需确认，只有显式声明安全的才自动放行：
- SQL 执行默认需确认（可在设置中开启"自动执行"）
- 图表修改走 ask（"确定要修改吗？"）
- 危险操作（DROP/ALTER/DELETE + LOAD_FILE/SLEEP/BENCHMARK）直接拒绝
- 语义层/数据源配置修改必须 admin 角色

**验收标准**：
- [ ] `DELETE FROM users` → 直接拒绝 + 记录审计
- [ ] `SELECT LOAD_FILE('/etc/passwd')` → 直接拒绝 + 记录审计
- [ ] 普通用户无法修改语义层配置

### SEC-02: SQL 安全校验（三层防线）

**对标**：Claude Code 沙箱 + 权限系统双防线

**第一层**：AST 解析拒绝非 SELECT（UPDATE/DELETE/DROP/ALTER/INSERT/TRUNCATE）
**第二层**：危险函数拒绝（LOAD_FILE/INTO OUTFILE/INTO DUMPFILE/SLEEP/BENCHMARK）
**第三层**：白名单列名校验（不在语义层定义内的列 → 拦截）

**验收标准**：
- [ ] 三层校验全部通过才允许执行
- [ ] 自愈生成的 SQL 也经过相同三层校验（v1 教训：自愈 prompt 无安全约束）
- [ ] 拦截记录完整审计日志（谁 + 原始 SQL + 拦截原因）

### SEC-03: 多租户框架级强制

**对标**：Claude Code Sandbox settings 强制 denyWrite — 不需要每次手动检查

SQLAlchemy session event 自动注入 `WHERE tenant_id = ?`：
- 新增 Model + API 不需要手动加 tenant_id 过滤
- 框架自动处理 — **新增 API 无法"忘加"租户条件**

**验收标准**：
- [ ] 租户 A 无法看到租户 B 的数据源、查询历史、语义层
- [ ] 新 API 即使没写 tenant_id 过滤，框架自动注入
- [ ] 跨租户访问尝试 → 审计记录 status=blocked

### SEC-04: 密钥安全

**对标**：Claude Code Trust 建立时序（启动时检测+拒绝启动）

- `.env.example` 中安全字段使用 `CHANGE_ME_<name>` 占位符
- 启动时检测占位符 → 拒绝启动 + 明确提示"请修改 xxx 密钥"
- Fernet 密钥从环境变量注入

**验收标准**：
- [ ] SECRET_KEY = "CHANGE_ME_SECRET_KEY" → 服务拒绝启动
- [ ] 日志不打印任何密钥内容

### SEC-05: 降级告警

**对标**：Claude Code 降级时 WARNING/ERROR 日志分级

- Redis 不可用 → WARNING 日志（缓存降级可接受）
- 限流/登录锁降级 → ERROR 日志（安全功能降级必须报警）
- 任何降级都可被监控系统采集

**验收标准**：
- [ ] Redis 连接失败 → 日志 level=WARNING + 监控指标可查询
- [ ] 限流失效 → 日志 level=ERROR + 告警

### SEC-06: 审计日志全覆盖

**对标**：Claude Code transcript — 所有操作全量记录（成功+失败+拒绝）

覆盖范围：查询成功 + 查询失败 + 权限拒绝 + SQL 注入拦截 + 登录成功 + 登录失败 + 数据源操作
统一字段：who(user_id) + when(timestamp) + what(resource_type/resource_id) + action + status(success/fail/denied) + sql_text + error

**验收标准**：
- [ ] 审计记录不可被业务用户删除
- [ ] 失败 + 拒绝操作有完整审计（v1 只有成功审计）
- [ ] SQL 注入拦截后审计记录含：user_id + "sql_injection_blocked" + 原始 SQL

## 五、Skills 业务规则系统

### SKL-01: SKILL.md 外置 + 热更新

**对标**：Claude Code Skills（SKILL.md + 条件触发 + 内嵌 Shell）

```
skills/
├── sql-rules/
│   └── SKILL.md          # SQL 生成规则
├── chart-rules/
│   └── SKILL.md          # 图表生成规则
└── business-rules/
    └── SKILL.md          # 业务领域规则
```

SKILL.md 格式：
```markdown
---
name: sql-rules
description: SQL 生成的业务规则
version: 1.0
---

## 时间字段规则
1. 所有时间过滤使用 created_at，不要用 update_time
2. 时间范围使用 BETWEEN 而非 >= AND <=

## 非空规则
1. 凡是查询列里的业务字段，WHERE 中拼接 IS NOT NULL

## GMV 计算规则
GMV = SUM(total_amount) WHERE status IN ('paid', 'shipped')
```

**热更新**：修改 SKILL.md → 下次查询立即使用新规则 → 不需重启服务

**验收标准**：
- [ ] 修改 SKILL.md 中 GMV 规则 → 下次查询"GMV"使用新定义
- [ ] 新增 SKILL.md → 系统自动加载（不需重启）
- [ ] Skills 变更记录（谁 + 什么时间 + 改了什么）

### SKL-02: 条件触发

**对标**：Claude Skills `paths` 字段（文件变更时自动激活）

```
---
paths: ["*.sql", "schema_*.json"]
---
```

某些 Skills 只在特定条件下激活。例如：某个数据源的 JSON 配置变更后，自动触发重新校验规则。

**验收标准**：
- [ ] 语义层 JSON 修改后 → 自动触发关联的校验 Skill

## 六、缓存与性能

### PERF-01: 两级缓存

**对标**：Claude Code compact 的 Session Memory 直挂（省 API）+ WrenAI 精确缓存 + 语义缓存

- **精确缓存**：相同问题 + 数据源 + 用户 → 直接返回（Redis，TTL 1 小时）
- **语义缓存**：向量相似度 > 0.95 → 复用 SQL 重新执行

**验收标准**：
- [ ] 问"本月销售额"→ 再问一次 → 精确缓存命中，< 500ms 返回
- [ ] 问"本月营收"→ 语义缓存命中（与"本月销售额"相似度 > 0.95）→ 复用 SQL

### PERF-02: Prompt 分层缓存

**对标**：Claude Code systemPromptSections — section 级缓存 + DYNAMIC_BOUNDARY

- 静态段（缓存 5 分钟）：语义层 context + Skills + 系统身份
- 动态段（每轮重新计算）：用户问题 + 对话历史 + 结构化状态

**验收标准**：
- [ ] 追问时语义层 context 复用缓存（不重新构建 prompt）
- [ ] 每组 section 的 token 消耗可查看（类似 `/context`）

### PERF-03: 异步查询

**对标**：Claude Code background agent + task notification

超过 10 秒的查询：提交后台任务 → 立即返回 task_id → 前端轮询或 SSE 推送状态

**验收标准**：
- [ ] 提交异步查询 → 立即返回 task_id + status=pending
- [ ] 轮询获取进度（pending → running → done/failed）
- [ ] 进度包含百分比 + 当前步骤描述

## 七、记忆与反馈

### MEM-01: Agent 记忆文件化

**对标**：Claude Code memdir — 每条记忆一个 .md 文件 + MEMORY.md 索引

每个 Agent（Intent/Schema/SQL/Chart）有独立的记忆目录：
- 存储位置：`.chatbi/memory/<agent-type>/`
- 格式：每条记忆一个 markdown 文件，MEMORY.md 做索引
- Agent 可自行读写（通过 FileWrite/FileEdit/FileRead 工具）
- 用户可通过 UI 查看、编辑、删除

**记忆类型**：
- user：用户偏好（"我习惯看柱状图"、"销售额默认指含税销售额"）
- project：项目事实（"orders 表的 status 枚举值有 pending/paid/shipped/cancelled"）
- session：当前会话摘要（"用户正在分析各品类销售数据"）

**验收标准**：
- [ ] Agent 记住"用户偏好折线图" → 下次自动默认用折线图
- [ ] 用户可通过数据字典界面查看 Agent 记住了什么
- [ ] 过时或错误的记忆可编辑或删除

### MEM-02: 反馈闭环（全方位）

**对标**：WrenAI Question-SQL Pair + Claude Code frustration detection + transcript sharing

**反馈维度**：
- **点赞/点踩**：最轻量的反馈信号
- **直接改 SQL**：用户修改 Agent 生成的 SQL → 修改后的版本作为正确答案存入知识库
- **纠正图表**：用户换了图表类型 → 记录偏好到记忆系统
- **写评论**：用户说明为什么不对 → 回流到语义层/Skills 优化

**自动触发**：
- 检测到负面信号（关键词匹配："不对"/"错了"/"没用"）→ 主动触发反馈收集
- 连续 2 次点踩 → 弹出 TranscriptSharePrompt（会话分享以帮助改进）

**验收标准**：
- [ ] 用户改过 SQL 后，下次相似问题使用修正后的版本
- [ ] 连续 2 次点踩 → 自动弹出反馈表单
- [ ] 反馈数据可按用户/数据源/时间筛选查看
