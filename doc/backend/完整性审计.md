## 3. Missing Features / Gaps

### Critical Gaps (Phase 1-2 planned, but absent)

1. **No Redis** -- Rate limiter is in-memory (process-local). Not production-distributed. PERF-01 Redis caching not present.
2. **No Chroma / Vector DB** -- RAG is keyword-based (n-gram + Levenshtein), not semantic vector search. SQL-03 not fully implemented.
3. **No multi-turn conversation** -- SQL-09: Each query is stateless. ChatView does not send previous messages to LLM.
4. **No Semantic Layer UI** -- META-08: DataSourceEditView is a placeholder. No alias/relationship/metric configuration UI.
5. **No Query History page** -- UX-04: API exists but no frontend route/page for viewing history.
6. **No Cursor-based pagination** -- API-04: All list endpoints use offset/limit, not cursor-based pagination.
7. **No LLM fallback** -- OPS-03: Single provider. If OpenAI/Dashscope goes down, all queries fail.

9. **No Email Verification page** -- Frontend has no `/verify-email` route (API exists, uses token link).

### Bugs / Issues Found

1. **Login lock is in-memory only** -- `login_lock_service.py` uses a Python dict. Multi-process or multi-instance deployment loses lock state. Should use Redis.
2. **Connection pool is in-memory** -- `ConnectionPoolManager._pools` is a class-level dict. App restart loses all pools (acceptable, but should be documented).
3. **SSE endpoint missing `progress` events** -- API-02 specifies `progress/sql/data/chart/complete/error` events. Current implementation has `intent/sql/data/chart/complete/error` but no `progress`.
4. **No email verification frontend route** -- Auth-08 requires email verification. API endpoint exists, but there is no `/verify-email` route in the frontend router. Users who click the email link land on a 404.
5. **UNION SELECT rejected** -- `test_unit.py` correctly identifies that UNION SELECT is rejected (parsed as `Union` node, not `Select`). This is overly strict -- UNION of SELECTs could be allowed.
6. **Self-heal only retries 2 times** -- Requirement SQL-06 says "最多 3 轮重试" (max 3 rounds). `self_heal.py` has `MAX_RETRY = 2`.

## 4. Security Posture Summary

### Authentication
- **Password hashing:** bcrypt with cost factor 12 -- Correct. Async execution avoids event loop blocking.
- **JWT:** HS256 with configurable secret key. Access token: 15 min expiry. Refresh token: 7 days with unique `jti` for rotation. Correct.
- **Password reset:** itsdangerous signed tokens, 30 min expiry. Correct.
- **Email verification:** itsdangerous signed tokens, 24h expiry. Unverified users cannot log in. Correct.
- **Login lock:** 5 failed attempts -> 15 min lock. In-memory only (not distributed-safe). Partial.

### Authorization
- **JWT-based auth:** All protected endpoints use `get_current_user` dependency. Correct.
- **Tenant isolation:** Application-layer filtering by `tenant_id` on all service queries. Correct for single-tenant-per-user model. No RLS at database level.
- **RBAC:** User has `role` field. Audit endpoint checks `role == "admin"`. No enforcement elsewhere. **Gap:** TENANT-03 RBAC not implemented.

### SQL Injection
- **AST validation:** SQLGlot parses and validates every SQL statement. Only SELECT allowed. Dangerous functions blocked. Sensitive tables blocked. Strong.
- **Read-only enforcement:** Transaction set to READ ONLY before execution. Strong.
- **Parameterized queries:** SQLAlchemy `text()` used for query execution. Correct.
- **Prompt injection:** System prompt instructs LLM to generate SELECT only. User input only in human message. Database read-only provides defense-in-depth.

### Data Encryption
- **Credentials at rest:** Fernet (AES-128-CBC) encryption for datasource username/password. Key derived from environment variable via SHA256. Correct.
- **Passwords:** bcrypt hashed, never stored or logged in plaintext. Correct.
- **Logs:** JSON formatter with email masking. No password logging. Correct.
- **In transit:** CORS configured for localhost. Production needs HTTPS. No TLS in application layer.
