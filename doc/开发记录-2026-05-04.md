## 关键修复

### 1. LLM 返回空内容问题
- **症状**: 旧接口 `192.168.3.110:18765` 的 `response_format={"type":"json_object"}` 返回空 content, 0 tokens
- **原因**: 旧接口不支持 JSON 模式
- **方案**: 切换到 DashScope (qwen3.6-plus)，`enable_thinking: false` 响应从 70s 降到 1-3s
- **结论**: JSON 模式是 LLM 应用的基础需求，必须支持

### 2. 本地缓存无法被清除
- **症状**: `redis-cli FLUSHDB` 后查询仍然返回缓存结果（0.0s 响应）
- **原因**: `cache_service._local_cache` 和 `intent._INTENT_CACHE` 是内存 dict，不受 Redis 操作影响
- **修复**: 移除所有本地缓存，统一走 Redis，重启进程即可清缓存

### 3. SQL 生成列名错误
- **症状**: "退款订单的支付方式分布" → LLM 生成 `SELECT payment_method FROM growth_records`
- **原因**: metadata config 中所有表的 description 字段为空，LLM 只看表名无法理解语义
- **修复**: 补全 10 张表 + 50+ 列的中文描述
- **结论**: 用户需要在"数据模型"页面填写表/列描述，否则 LLM 只能瞎猜

### 4. 自愈后 SQL 未回写
- **修复**: graph.py 中 self_heal 节点返回的 fixed SQL 回写到 state["sql"]
