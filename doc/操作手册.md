## 1. 快速开始

### 1.1 系统简介

ChatBI 是一个基于 AI 的自助数据分析平台。用户只需用自然语言提问，系统即可：

1. 理解用户意图（数据查询 or 其他）
2. 自动选择相关表结构（LLM 两步 Schema 选择（选表+选字段））
3. 生成 SQL 查询
4. 执行查询并获取数据
5. 自动选择合适的图表类型
6. 展示数据表格和图表

**核心特性**：SQL 自愈（自动修正错误 SQL）、多数据源支持、多租户隔离、审计日志、CSV 导出

### 1.2 技术栈

| 层级 | 技术 |
|------|------|
| 后端 | Python 3.12+, FastAPI, SQLAlchemy async |
| AI | LangGraph, LangChain, OpenAI-compatible API |
| 数据库 | MySQL 9.4 @ 192.168.3.110:3306 (开发/生产) |
| 缓存 | Redis @ 192.168.3.110:6379 (查询缓存、限流、登录锁) |
| 前端 | Vue 3, TypeScript, Element Plus, ECharts |
| 安全 | JWT(HS256), bcrypt, Fernet 加密, SQLGlot AST 校验 |

### 1.3 5 分钟上手

```bash
# 1. 安装依赖
cd backend
pip install -r requirements.txt

# 2. 配置环境
# .env 已预配置 MySQL + Redis，直接使用
# 如需修改，编辑 backend/.env

# 3. 初始化数据库（DDL 建表 + seed.py 灌数据）
cd backend
# DDL 建表（只需首次）
python -c "
import asyncio, aiomysql
async def main():
    conn = await aiomysql.connect(host='192.168.3.110', port=3306, user='root', password='yjt_mysql')
    cur = await conn.cursor()
    await cur.execute('CREATE DATABASE IF NOT EXISTS chatbi CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci')
    await conn.ensure_closed()
asyncio.run(main())
"
# 执行 DDL（建 9 张表）
python -c "
import asyncio, aiomysql
async def main():
    conn = await aiomysql.connect(host='192.168.3.110', port=3306, user='root', password='yjt_mysql', db='chatbi')
    with open('init-chatbi.sql', 'r') as f:
        sql = f.read()
    statements = [s.strip() for s in sql.split(';') if s.strip() and not s.strip().startswith('--')]
    cur = await conn.cursor()
    for stmt in statements:
        if stmt:
            await cur.execute(stmt)
    await conn.commit()
    await conn.ensure_closed()
asyncio.run(main())
"
# 灌入业务数据
python seed.py

# 4. 启动后端
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# 5. 前端（另开终端）
cd ../frontend
npm install
npm run dev

# 6. 浏览器访问 http://localhost:5173
# 使用 admin@chatbi.com / Test1234! 登录
```

## 2. 环境配置

### 2.1 环境变量

`.env` 已预配置好 MySQL 和 Redis，开发环境可直接使用：

```bash
# MySQL（ChatBI 自身数据库）
DATABASE_URL=mysql+aiomysql://root:yjt_mysql@192.168.3.110:3306/chatbi

# Redis（查询缓存、限流、登录锁）
REDIS_URL=redis://192.168.3.110:6379/0

```

如需修改，编辑 `backend/.env`：

| 变量 | 必填 | 说明 | 示例 |
|------|------|------|------|
| `APP_ENV` | 否 | 运行环境 | `development` / `production` |

| `DATABASE_URL` | 否 | 数据库连接串（默认 SQLite） | `sqlite+aiosqlite:///./chatbi.db` |
| `LLM_BASE_URL` | 否 | LLM API 地址（默认 OpenAI） | `https://api.openai.com/v1` |
| `LLM_API_KEY` | **是** | LLM API Key | `sk-xxx` |
| `LLM_MODEL` | 否 | LLM 模型名 | `gpt-4o` |
| `SMTP_HOST` | 否 | SMTP 服务器（邮箱验证需要） | `smtp.gmail.com` |
| `SMTP_PORT` | 否 | SMTP 端口 | `587` |
| `SMTP_USER` | 否 | SMTP 用户名 | `noreply@example.com` |
| `SMTP_PASSWORD` | 否 | SMTP 密码 | `app_password` |
| `SMTP_FROM` | 否 | 发件人地址 | `ChatBI <noreply@example.com>` |
| `CORS_ORIGINS` | 否 | 前端跨域白名单 | `["http://localhost:5173"]` |
| `FRONTEND_URL` | 否 | 前端 URL（邮件链接用） | `http://localhost:5173` |

## 4. 用户操作指南

### 4.1 注册与登录

1. 访问注册页，输入邮箱和密码（最少 8 位，需含字母+数字）
2. 点击注册后，系统发送验证邮件
3. 点击邮件中的验证链接完成验证
4. 使用邮箱+密码登录

**登录失败锁定**：连续 5 次密码错误将锁定账号 15 分钟。

### 4.2 密码重置

1. 在登录页点击「忘记密码」
2. 输入注册邮箱
3. 查收邮件中的重置链接（30 分钟有效）
4. 设置新密码

### 4.3 添加数据源

1. 登录后进入「数据源管理」页
2. 点击「新增数据源」
3. 填写：
   - 数据源名称（如 "生产 MySQL"）
   - 数据库类型（MySQL / PostgreSQL）
   - 主机地址、端口、数据库名
   - 用户名、密码
4. 点击「测试连接」验证连通性
5. 点击「保存」
6. 点击「扫描表结构」扫描 metadata（AI 查询需要）

### 4.4 发起查询

1. 在对话页选择数据源
2. 用自然语言输入问题，如：
   - "上个月的销售总额是多少？"
   - "每个部门的员工数量"
   - "最近 30 天的订单趋势"
3. 按 Enter 发送
4. 系统自动：
   - 识别意图
   - 检索相关表结构
   - 生成 SQL
   - 执行查询
   - 选择图表类型
5. 查看结果表格和图表

### 4.5 保存查询

点击查询结果旁的「保存」按钮，输入名称即可保存。之后可在「查询历史」页查看和重跑。

### 4.6 导出 CSV

在查询结果页点击「导出 CSV」按钮，下载当前查询结果为 CSV 文件。

### 4.7 反馈

对查询结果点击 👍 或 👎，可帮助系统改进。

## 5. API 接口文档

### 5.1 认证

#### POST /api/v1/auth/register

注册新用户。

```json
// 请求
{"email": "user@example.com", "password": "Test1234!"}

// 响应 201
{"message": "注册成功，请查收验证邮件"}
```

#### POST /api/v1/auth/login

登录获取 token。

```json
// 请求
{"email": "user@example.com", "password": "Test1234!"}

// 响应 200
{
  "access_token": "eyJ...",
  "refresh_token": "eyJ..."
}
```

后续请求需在 Header 中携带：`Authorization: Bearer <access_token>`

#### POST /api/v1/auth/refresh

刷新 access token。

```json
// 请求
{"refresh_token": "eyJ..."}

// 响应 200
{"access_token": "新的access_token", "refresh_token": "新的refresh_token"}
```

#### POST /api/v1/auth/verify-email

验证邮箱。

```json
// 请求
{"token": "从邮件链接获取"}

// 响应 200
{"message": "邮箱已验证"}
```

#### POST /api/v1/auth/reset-password

请求密码重置邮件。

```json
// 请求
{"email": "user@example.com"}

// 响应 200
{"message": "如果邮箱存在，重置链接已发送"}
```

#### POST /api/v1/auth/reset-password/confirm

确认密码重置。

```json
// 请求
{"token": "从邮件链接获取", "new_password": "NewPass123!"}

// 响应 200
{"message": "密码已重置"}
```

SSE 流式查询，逐步推送进度。

```
event: data
```

## 6. 数据源管理

### 6.1 支持的数据库

| 类型 | 驱动 | 端口默认 |
|------|------|---------|
| MySQL | aiomysql | 3306 |
| PostgreSQL | asyncpg | 5432 |

### 6.2 连接池

每个数据源创建独立的连接池（配置来自 `config.py`）：
- `pool_size`: 5 (DB_POOL_SIZE)
- `max_overflow`: 10 (DB_POOL_MAX_OVERFLOW)
- `pool_timeout`: 30 秒 (DB_POOL_TIMEOUT)
- `pool_recycle`: 3600 秒（1 小时回收, DB_POOL_RECYCLE）
- `pool_pre_ping`: 是（连接前检测有效性）

### 6.3 连接加密

数据源的用户名和密码使用 Fernet 对称加密存储，数据库中不保存明文。

### 6.4 健康检查

每次连接测试后更新 `is_active` 状态和 `last_health_check` 时间。

### 6.5 表结构扫描

`POST /datasources/{id}/scan` 扫描 `INFORMATION_SCHEMA` 获取：
- 表名、表注释
- 字段名、类型、是否可空、注释
- 主键、外键关系

扫描结果保存为 JSON 格式存入 `metadata_configs` 表，供 AI 查询时 RAG 检索使用。

## 7. AI 查询系统

### 7.1 查询流程

```
用户提问
  │
  ▼
┌─────────────────┐
│ 1. 意图分类     │  LLM: DataQuery 或 Other
└────────┬────────┘
         │
    DataQuery?
    /       \
  是         否 → 返回错误提示
  │
  ▼
┌─────────────────┐
│ 2. 上下文补全   │  多轮追问时补全指代、省略
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 3. Schema 选择  │  LLM 两步：先选相关表，再选所需字段
│  (LLM 两步)     │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 4. SQL 生成     │  LLM: 根据 schema + 问题生成 SQL
│ (含 AST 校验)   │  SQLGlot: 仅允许 SELECT，嵌入校验
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 5. 执行查询     │  连接池执行, 30s 超时
│  (只读模式)     │  最多 1000 行
└────────┬────────┘
         │
    成功?
    /    \
  是      否 → 自愈(最多 2 轮)
  │          │
  │     ┌────▼────┐
  │     │错误分析 │→ LLM 修复 SQL → 重新验证 → 重新执行
  │     └─────────┘
  │
  ▼
┌─────────────────┐
│ 6. 图表推断     │  根据数据特征自动选图
└────────┬────────┘
         │
         ▼
      返回结果
```

### 7.2 SQL 安全校验

使用 SQLGlot AST 解析，多层防护：

1. **节点类型检查**：仅允许 `SELECT` 节点，拒绝 `DROP/DELETE/INSERT/UPDATE/CREATE/ALTER/GRANT/TRUNCATE`
2. **危险函数拦截**：`SLEEP, BENCHMARK, LOAD_FILE, sys_exec, sys_eval, pg_read_file, xp_cmdshell` 等
3. **系统表拦截**：`mysql.user, mysql.db, information_schema.user_privileges, pg_catalog.pg_authid, pg_shadow`
4. **执行层只读**：MySQL `SET SESSION TRANSACTION READ ONLY` / PostgreSQL `SET default_transaction_read_only = on`

### 7.3 SQL 自愈

执行失败时自动修复，最多 2 轮重试（可通过 `LLM_SELF_HEAL_MAX_RETRIES` 配置）：

1. 分析错误类型（MySQL 错误码映射）
2. 构建修复 prompt（含原始 SQL + 错误信息 + schema）
3. LLM 生成修复 SQL
4. 通过 AST 校验后重新执行

可自动修复的常见错误：
- `1146` — 表不存在（LLM 选择其他相似表）
- `1054` — 列不存在（LLM 替换为正确列名）
- `1064` — SQL 语法错误
- `1049` — 数据库不存在

### 7.4 图表推断规则

| 数据特征 | 图表类型 |
|---------|---------|
| 1列1行 | metric (指标卡) |
| 2列：时间+数值 | line (折线图) |
| 2列：分类+数值, ≤5行 | pie (饼图) |
| 2列：分类+数值 | bar (柱状图) |
| 3列：分类+分类+数值 | grouped_bar (分组柱状图) |
| 多列多行, 2+数值列 | scatter (散点图) |
| 其他 | table (表格) |

### 7.5 Schema 选择（LLM 两步）

基于 LLM 的两步 Schema 选择，替代传统的 RAG 关键词检索：

**第一步：选表**
- LLM 根据用户问题 + 所有表的名称/说明/关联关系，选择相关表
- 输入：用户问题、所有表名及表说明、表间关联关系
- 输出：与问题相关的表列表

**第二步：选字段**
- LLM 根据选中表的字段列表，选择需要的字段
- 输入：用户问题、选中表的完整字段列表（名称、类型、注释）
- 输出：每张表所需的字段子集（主键/外键始终包含）

**构建 schema_context**
- 将选中的表和字段组合为精确的 schema_context，供 SQL 生成节点使用
- 相比关键词匹配，LLM 能理解语义关联，选表更精准

**附加：防捏造**
- 在 schema_context 中附带所有表名列表，防止 LLM 捏造不存在的表名

### 7.6 多轮对话追问

系统支持上下文追问解析，自动识别并补全语义：

- "上个月呢？" → 继承上一个问题的时间维度，替换为"上个月"
- "按城市排序呢" → 追加到上一个问题后面
- "换个方式统计" → 以上一个问题为基础重新查询

追问识别基于：代词（那、这个）、时间词（上个月、本周）、动作词（排序、过滤、分组）。

### 7.7 SQL 解释

查询成功后，系统自动用自然语言解释 SQL 做了什么：

```json
{
  "sql_explanation": "查询2024年每个月的订单总数、总GMV和平均订单金额"
}
```

如果 LLM 解释失败，该字段为 `null`，不影响查询结果返回。

### 7.8 敏感数据脱敏

查询结果中自动检测并脱敏敏感字段（手机号、身份证、邮箱等）：

| 原始值 | 脱敏后 |
|--------|--------|
| 13812345678 | 138****5678 |
| 110101199001011234 | ***************1234 |
| user@example.com | u***@example.com |

脱敏规则定义在 `app/services/data_masking.py`，基于列名匹配和数据模式识别。

### 7.9 查询缓存

系统使用 Redis 缓存精确查询结果：

- **Cache Key**: SHA256(question + datasource_id)
- **TTL**: 3600 秒（可通过 `QUERY_CACHE_TTL_SECONDS` 配置）
- **命中条件**: 完全相同的问题 + 数据源
- **回退**: Redis 不可用时自动降级到内存缓存
- **不缓存**: 失败的查询、空结果

| 限制项 | 值 | 说明 |
|--------|-----|------|
| 查询总超时 | 35 秒 | 非流式接口 |
| 流式查询超时 | 60 秒 | SSE 接口 |
| SQL 执行超时 | 30 秒 | 单次执行 |
| 最大返回行数 | 1000 | 超出自动截断 |
| LLM max_tokens | 2000 | SQL 生成 |
| 自愈重试次数 | 2 次 | 超过返回失败 |

## 8. 安全与权限

### 8.1 认证机制

- **JWT (HS256)**: access token 15 分钟有效，refresh token 7 天有效
- **bcrypt**: 密码 hash，cost factor 12
- **邮箱验证**: 注册后必须验证邮箱才能登录
- **登录锁定**: 连续 5 次失败锁定 15 分钟（存储于 Redis 或内存）

### 8.2 多租户隔离

- 每个用户自动创建独立 tenant
- 所有查询强制带 `tenant_id` 过滤
- 数据源、审计日志、分析事件均按租户隔离

### 8.3 角色权限

| 操作 | user | admin |
|------|------|-------|
| 登录/查询/数据源 CRUD | ✅ | ✅ |
| 查看审计日志 | ❌ | ✅ |

设置管理员：

```sql
-- 在数据库中修改用户角色
UPDATE users SET role = 'admin' WHERE email = 'admin@example.com';
```

### 8.4 安全头

所有响应自动包含：
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Content-Security-Policy: default-src 'self'`

### 8.5 限流策略

| 端点 | 限制 |
|------|------|
| /auth/login | 10 次/分钟/IP |
| /query | 30 次/分钟/IP |
| 其他 API | 60 次/分钟/IP |

限流数据存储：
- 无 Redis 时：内存字典（单机适用）
- 有 Redis 时：Redis 存储（多实例共享，推荐）

### 8.6 CSV 注入防护

导出 CSV 时，如果单元格以 `=`, `+`, `-`, `@` 开头，自动前缀 `'` 防止公式注入。

## 10. 故障排查

### 10.1 常见问题

#### 注册后无法登录

**症状**：登录返回 403 `EMAIL_NOT_VERIFIED`

**原因**：SMTP 未配置，验证邮件未发出

**解决**：
1. 检查 `.env` 中 SMTP 配置是否正确
2. 如果开发环境不需要邮件，可在数据库中手动验证：
   ```sql
   UPDATE users SET email_verified = true WHERE email = 'user@example.com';
   ```

#### 查询返回 "无法生成 SQL"

**症状**：`success: false, error: "无法生成 SQL"`

**原因**：
- LLM API Key 未配置或无效
- LLM 返回了空响应

**解决**：
1. 检查 `LLM_API_KEY` 是否正确
2. 检查 `LLM_BASE_URL` 是否可达
3. 查看后端日志中的 LLM 调用错误

#### SQL 执行失败

**症状**：`success: false, error: "SQL 执行失败: ..."`

**排查**：
1. 检查数据源是否已扫描表结构（`POST /datasources/{id}/scan`）
2. 检查 SQL 是否包含不存在的表/字段
3. 查看是否触发了 AST 安全校验被拦截
4. 确认数据源连接正常（`POST /datasources/{id}/test`）

#### 数据源连接测试失败

**症状**：`CONNECTION_FAILED`

**排查**：
1. 确认数据库主机、端口、数据库名正确
2. 确认数据库允许来自 ChatBI 服务器的连接
3. 确认用户名密码正确
4. 检查防火墙规则

#### 查询超时

**症状**：`"查询超时（35秒限制）"` 或 `"查询超时（60秒限制）"`

**解决**：
1. 优化 SQL 查询（添加索引）
2. 减少查询范围（添加 WHERE 条件限制时间范围）
3. 确认数据库性能正常

#### 限流 429

**症状**：`RATE_LIMITED`

**解决**：
1. 等待 1 分钟后重试（登录限制）
2. 减少请求频率
3. 生产环境考虑调高限流阈值（`rate_limiter.py`）

### 10.2 错误码速查

| 错误码 | 原因 | 解决方案 |
|--------|------|---------|
| `DATASOURCE_NOT_FOUND` | 数据源不存在或无权限 | 检查数据源 ID 和租户 |
| `EMAIL_EXISTS` | 邮箱已注册 | 直接登录或重置密码 |
| `INVALID_CREDENTIALS` | 邮箱或密码错误 | 确认密码或重置 |
| `INVALID_TOKEN` | Token 无效/过期 | 重新登录 |
| `EMAIL_NOT_VERIFIED` | 邮箱未验证 | 查收验证邮件或手动验证 |
| `ACCOUNT_LOCKED` | 登录失败次数过多 | 等待 15 分钟 |
| `RATE_LIMITED` | 请求过于频繁 | 降低请求频率 |
| `ADMIN_REQUIRED` | 需要管理员权限 | 联系管理员 |
| `NO_DATA` | 无数据可导出 | 先执行查询再导出 |
| `CONNECTION_FAILED` | 数据源连接失败 | 检查连接参数 |
| `NOT_FOUND` | 资源不存在 | 检查 ID |
| `INVALID_RATING` | 反馈评分无效 | 使用 "up" 或 "down" |

```nginx
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # SSE 流式支持
    location /chat-bi/api/v1/query/stream {
        proxy_pass http://127.0.0.1:8080;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 60s;
        proxy_set_header Connection '';
        proxy_http_version 1.1;
        chunked_transfer_encoding off;
    }
}
```

### 11.9 故障排查

**容器启动失败**：
```bash
# 查看完整日志
docker compose logs chatbi

# 检查配置是否生效
docker exec chatbi cat /app/backend/.env.production
```

**后端无法连接数据库**：
```bash
# 确认 mysql 容器健康
docker compose ps mysql

# 从 chatbi 容器内测试连通性
docker exec chatbi python -c "
import asyncio, aiomysql
async def test():
    conn = await aiomysql.connect(host='mysql', port=3306, user='root', password='yjt_mysql')
    print('MySQL connected!')
    await conn.ensure_closed()
asyncio.run(test())
"
```

**Nginx 代理 502**：
```bash
# 确认后端活着
docker exec chatbi curl -s http://127.0.0.1:8000/health

# 确认 nginx 配置
docker exec chatbi nginx -t
```
